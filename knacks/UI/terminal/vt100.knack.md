# VT100 Compatibility

## When to Load This Knack

Load this knack when a program, emulator, or terminfo entry claims VT100
compatibility and exact cursor, keypad, line-drawing, wrap, or scrolling
behavior matters.

## Mental Model

The DEC VT100 is a historical baseline for modern terminal behavior, not a
complete description of a modern emulator. The original hardware had:

- no modern color model;
- no Unicode;
- specific autowrap, scrolling-margin, and origin-mode behavior;
- normal and application keypad modes;
- DEC Special Graphics for line drawing; and
- an optional VT52 compatibility mode.

Treat "VT100-compatible" as a rough control-vocabulary floor. For exact
behavior, use the DEC manuals and a terminal test suite.

## Important Behavior

Cursor and erase functions such as `CUU`, `CUD`, `CUF`, `CUB`, `CUP`, `ED`,
and `EL` form part of the core working set.

Scrolling regions interact with origin mode:

- `DECOM` changes whether addressing is relative to the whole screen or the
  active scrolling region.
- `DECAWM` controls autowrap.
- keypad and cursor-key modes change the sequences keys transmit.

VT100 line drawing uses DEC Special Graphics, not Unicode box-drawing
characters. Modern emulators may translate those glyphs, but legacy
applications can still select the character set explicitly.

## Modern Extensions

Modern emulators often add:

- color and extended rendition;
- VT220 and later DEC controls;
- mouse and focus reporting;
- alternate-screen buffers;
- title and clipboard operations; and
- UTF-8 and wide-character rendering.

An application can therefore fail in two directions: it may assume too little
and miss useful features, or assume xterm-era behavior while advertising a
strict VT100 identity.

Keep emulator identity, `$TERM`, terminfo, and emitted traffic aligned.

## Sharp Edges

Right-edge autowrap behavior is not the simple immediate-wrap model many
programs assume. Bugs confined to the last column often expose terminal
semantics rather than an ordinary application off-by-one error.

Do not use "VT100" to describe every escape sequence found in modern terminal
documentation. Do not assume broken line drawing is only a font problem; it
may involve character-set selection, terminfo, or a Unicode conversion path.

## Debugging Checklist

- Confirm the emulator's claimed identity and `$TERM`.
- Classify the sequence as VT100, later DEC, or emulator-specific.
- Inspect origin, wrap, keypad, and cursor-key modes.
- Test last-column and scrolling-region behavior explicitly.
- Reproduce with `vttest` when separating application and emulator defects.
