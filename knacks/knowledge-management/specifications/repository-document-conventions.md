# Repository Document Conventions

Status: Draft

## Purpose

Define how knowledge-base and working documents are stored, linked, and
exposed in a project's chosen viewer.

## Initial Direction

- Use Markdown by default for proposals, bugs, backlog files, working notes,
  and other project-management artifacts.
- Make active repository workflow Markdown browsable when the project has a
  documentation viewer.
- Give each browsable Markdown document a unique top-level `#` heading.
- Use standard Markdown links by default. Adopt wiki links only when the
  project's tooling defines and validates their resolution.
